# Drawry 장소·네이버 지도 도입 계획

> 문서 상태: 후속 구현 계획
>
> 1차 MVP 포함 여부: 제외
>
> 도입 순서: 2차 장소 기록 → 3차 네이버 지도
>
> 마지막 검토: 2026-08-30

## 1. 분리 목적

장소와 지도는 그림일기 핵심 작성·보관 기능이 안정화된 뒤 추가한다. 1차 MVP에서는 화면, 데이터베이스, 권한, 백업 포맷과 외부 비용에 위치 기능을 끼워 넣지 않는다. 이 문서는 나중에 다시 조사하지 않아도 구현할 수 있도록 확정된 요구사항, 단계별 범위, 데이터 구조, 비용 통제와 검증 기준을 보존한다.

지도는 장소 검색이나 길찾기가 아니라 `기록한 위치를 나중에 떠올리는 용도`로만 사용한다. 공개 프로필, 사용자 위치 공유, 경로 기록과 백그라운드 위치 추적은 도입하지 않는다.

## 2. 버전별 범위

| 차수 | 범위 | 포함 기능 | 포함하지 않는 기능 |
| --- | --- | --- | --- |
| 1차 MVP | 장소·지도 없음 | 일기·미디어·날짜·텍스트·기분·태그·수동 날씨 기록 | 장소 필드, GPS 읽기, 위치 권한, NAVER Maps SDK, 자동 위치 기반 날씨 |
| 2차 | 장소 기록 | 장소명 직접 입력, 선택적 사진 GPS·현재 위치 좌표, 위치 카드, 장소 백업·복원, 좌표 기반 과거 날씨 제안 | 앱 내부 지도, 지도 핀 선택, 장소·주소 검색, 추억 지도 |
| 3차 | 네이버 지도 | 지도에서 핀 선택, 저장 위치 보기, 현재 위치 표시, 추억 지도, 마커·클러스터 | 상호·기관 검색, 주소 검색, 주변 추천, 길찾기, 경로 기록, 백그라운드 추적 |

2차와 3차는 각각 별도 출시 가능한 단위로 만든다. 2차 데이터 구조가 안정되기 전에는 3차 지도 SDK를 앱 의존성에 추가하지 않는다.

## 3. 1차 MVP에서 지켜야 할 경계

- `Place`, 위도·경도와 위치 출처 필드를 1차 데이터베이스에 미리 만들지 않는다.
- 사진·영상의 GPS 메타데이터를 읽기 위한 권한을 요청하지 않는다.
- 현재 위치 권한 문구와 플랫폼 설정을 추가하지 않는다.
- `flutter_naver_map`과 NAVER Maps 네이티브 SDK를 설치하지 않는다.
- 지도 화면, 지도 딥 링크, 마커 이미지와 NAVER Cloud 인증 정보를 포함하지 않는다.
- 공유 이미지와 암호화 백업의 1차 포맷에 장소 항목을 넣지 않는다.
- 자동 과거 날씨 조회는 위치에 의존하므로 2차까지 보류한다. 1차 날씨는 사용자가 직접 기록하는 선택 항목만 지원한다.

이 경계를 자동 테스트와 릴리스 체크리스트에 넣어 위치 기능이 실수로 1차 앱에 포함되지 않게 한다.

## 4. 2차 구현: 장소 기록

### 4.1 사용자 기능

- 일기 등록·수정 화면에 선택형 `장소` 영역을 추가한다.
- 사용자는 좌표 없이 장소명만 직접 입력할 수 있다.
- 사용자가 명시적으로 허용한 경우에만 선택한 사진·영상의 GPS를 위치 후보로 읽는다.
- 사용자가 `현재 위치 사용`을 누른 경우에만 운영체제 위치 권한을 요청하고 한 번 얻은 좌표를 후보로 사용한다.
- 여러 미디어의 GPS가 다르면 자동 확정하지 않고 후보 목록에서 하나를 선택하게 한다.
- 장소명과 좌표는 각각 제거할 수 있으며, 좌표 없이 장소명만 저장할 수 있다.
- 상세 화면은 장소가 있을 때 텍스트 기반 위치 카드만 표시한다. 앱 내부 지도는 열지 않는다.
- 공유 버튼을 누르면 장소명 포함 여부를 선택하게 하고 직전 선택을 기억한다. 정확한 좌표는 공유하지 않는다.

### 4.2 데이터 모델과 마이그레이션

2차 데이터베이스 마이그레이션에서 다음 구조를 추가한다.

| 필드 | 형식 | 규칙 |
| --- | --- | --- |
| diaryId | 일기 식별자 | 일기와 1:0..1 관계 |
| displayName | 문자열, 선택 | 사용자가 확인·수정한 표시명 |
| latitude | 암호화 실수, 선택 | `-90..90`; displayName만 저장할 때는 없음 |
| longitude | 암호화 실수, 선택 | `-180..180`; latitude와 함께 존재해야 함 |
| source | 열거형 | `manual`, `mediaMetadata`, `currentLocation` |
| confirmedAt | 시각 | 사용자가 후보를 확정한 시각 |

- 위치 데이터는 일기 데이터베이스와 같은 수준으로 암호화한다.
- 로그, 오류 보고와 분석 이벤트에 좌표·장소명·미디어 경로를 기록하지 않는다.
- 1차 백업 복원은 장소 없음으로 정상 처리하고, 2차 백업은 장소 필드를 선택적으로 포함한다.
- 2차 데이터를 1차 앱에서 열어야 하는 하위 호환은 보장하지 않고 백업 포맷 버전으로 차단한다.
- 장소 제거 시 레코드와 관련 키·임시 메타데이터를 함께 정리한다.

### 4.3 과거 날씨 연결

- 1차에서 사용자가 직접 기록한 날씨는 그대로 유지한다.
- 2차부터 확정 좌표와 과거 날짜가 모두 있을 때만 `과거 날씨 가져오기`를 제안한다.
- 기기 안에서 가장 가까운 기상청 ASOS 관측소를 계산하고 서버리스 함수에는 `관측소 번호 + 과거 날짜`만 전송한다.
- 오늘·미래 날짜에는 과거 날씨를 자동 조회하지 않는다.
- 결과는 자동 확정하지 않고 사용자가 확인·수정·삭제할 수 있는 스냅샷으로 저장한다.
- 날짜 또는 좌표가 바뀌면 기존 날씨가 일치하지 않을 수 있음을 표시하고 다시 조회·유지·삭제를 선택하게 한다.
- 위치가 없으면 기존처럼 날씨를 직접 기록하거나 비워 둘 수 있다.

### 4.4 2차 완료 기준

- 위치 권한을 거부해도 장소명 직접 입력과 일기 저장이 가능하다.
- 좌표·장소명이 데이터베이스, 백업과 임시 파일에서 암호화된다.
- 원본 GPS와 정확한 좌표가 공유 이미지·EXIF·로그에 포함되지 않는다.
- 기존 1차 일기·백업을 데이터 손실 없이 마이그레이션·복원할 수 있다.
- 앱 내부 지도 SDK 없이 장소 등록·수정·제거·표시가 모두 동작한다.
- 과거 날씨 API 장애가 일기 저장을 막지 않는다.

## 5. 3차 구현: 네이버 지도

### 5.1 지도 서비스

지도 표시는 iOS·Android용 `NAVER Maps Mobile Dynamic Map SDK`를 사용한다. 좌표와 사용자가 작성한 장소명만 영구 저장하며 Geocoding, Reverse Geocoding, Static Map, Directions와 네이버 지역 검색 API는 사용하지 않는다.

Flutter에서는 `flutter_naver_map`을 내부 `MapPort` 뒤에 연결한다. 실기기 검증에서 플랫폼 뷰 수명 주기, 메모리, 검은 화면 또는 기능 문제가 확인되면 앱의 장소 도메인은 유지하고 Android·iOS 공식 SDK를 감싼 자체 Flutter 플러그인으로 교체한다.

### 5.2 화면과 사용자 흐름

#### 장소 선택 지도

1. 저장된 미디어 GPS, 2차에서 저장한 좌표 또는 현재 위치를 후보 핀으로 연다.
2. 사용자가 지도를 이동하거나 지점을 길게 눌러 핀을 지정한다.
3. 사용자가 장소명을 직접 입력하거나 수정한다.
4. 좌표와 장소명을 확인한 뒤 저장하거나 위치를 완전히 제거한다.

#### 일기 상세

- 상세 첫 화면은 장소명과 `지도 열기` 버튼이 있는 로컬 위치 카드만 표시한다.
- 사용자가 `지도 열기`를 눌렀을 때만 NAVER 지도 위젯을 생성한다.
- 오프라인·인증 실패·한도 초과 시 위치 카드를 유지하고 필요하면 공식 `nmap://place` URL Scheme으로 네이버 지도 앱을 연다.

#### 추억 지도

- 화면당 지도 인스턴스 한 개만 생성한다.
- 기기에 저장된 모든 일기 좌표를 마커로 표시하고 밀집 구간은 클러스터링한다.
- 마커를 누르면 날짜·대표 썸네일·장소명을 담은 하단 카드를 열고 일기 상세로 이동한다.
- 날짜·태그·기분 필터는 로컬 데이터에만 적용하며 필터 변경 때문에 지도 위젯을 재생성하지 않는다.

### 5.3 비용 최소화 설계

3차 초기 목표는 NAVER Cloud Maps 비용 `월 0원`이다.

| 항목 | 계획 |
| --- | --- |
| 사용 서비스 | Mobile Dynamic Map만 사용 |
| 사용하지 않음 | Geocoding, Reverse Geocoding, Static Map, Directions, NAVER Cloud 서버·DB·Object Storage |
| 무료 범위 | 대표 계정 월 6,000,000건 |
| 무료 초과 단가 | 0.1원/건, VAT 별도 |
| 개발 초기 한도 | 일 1,000건·월 20,000건, 초과 사용 끔 |
| 비공개 베타 한도 | 일 10,000건·월 200,000건, 초과 사용 끔 |
| 정식 운영 안전 상한 | 월 5,500,000건, 비용 승인 없이는 상향 금지 |
| 알림 | 50%, 80%, 90%, 100% |

호출 억제 원칙:

1. 피드, 캘린더, 검색 결과, 공유 이미지와 상세 첫 화면에서는 지도 위젯을 생성하지 않는다.
2. 장소가 없는 일기의 등록·상세 화면에서는 지도 SDK를 초기화하지 않는다.
3. 추억 지도는 화면당 지도 한 개에 모든 마커를 표시한다. 일기별 지도와 Static Map 썸네일을 만들지 않는다.
4. Flutter 상태 변경, 하단 시트와 마커 변경 때문에 지도 위젯이 재생성되지 않도록 지도 컨트롤러 수명 주기를 화면 상태와 분리한다.
5. 화면을 나가면 지도 컨트롤러와 플랫폼 뷰를 정상 해제한다.
6. SDK 캐시는 임의로 삭제하지 않지만 캐시가 과금 건수를 줄인다고 가정하지 않는다.
7. 라이트 모드는 메모리·로딩 절감 목적으로만 검증하고 과금 절감으로 계산하지 않는다.
8. 개발·운영 Application을 분리하되 대표 계정 무료량이 합산될 수 있으므로 전체 Usage도 함께 감시한다.

공식 문서가 SDK의 정확한 과금 이벤트를 상세히 정의하지 않으므로 `지도 위젯 초기화 1회 = 과금 1건`으로 확정하지 않는다. 베타에서 정해진 초기화·복귀·재생성 시나리오를 반복하고 NAVER Cloud Usage의 약 1분 지연 반영값과 대조해 실제 과금 단위를 확정한다.

실측 전 참고치로 활성 사용자 한 명이 월 25회 지도를 초기화한다고 가정하면 월 6,000,000건은 약 240,000 MAU에 해당한다. 이는 예산 추정일 뿐이며 실측 뒤 다시 계산한다.

### 5.4 보안과 개인정보

- 정확한 좌표와 장소명은 기기 내부에서 암호화한다.
- 위치 권한은 현재 위치 기능을 사용한 순간에만 요청하고 `항상 허용` 권한을 요구하지 않는다.
- 백그라운드 위치 추적과 이동 경로 수집을 구현하지 않는다.
- 공유 이미지는 정확한 좌표와 원본 GPS EXIF를 제거하고 장소명만 사용자 선택으로 포함한다.
- 지도 SDK와 외부 서비스가 처리하는 정보·목적을 개인정보 처리방침과 스토어 개인정보 항목에 반영한다.
- 지도 Client ID는 Android 패키지명과 iOS Bundle ID로 제한하고 개발·운영 Application을 분리한다.

### 5.5 장애와 대체 흐름

- 지도 로딩 실패: 장소명·위치 카드·직접 입력을 유지한다.
- 네트워크 없음: 좌표와 장소 저장은 허용하고 지도만 다시 시도한다.
- 위치 권한 거부: 저장 좌표 또는 지도 수동 핀을 사용하고, 둘 다 원하지 않으면 장소명만 저장한다.
- `429 QuotaExceeded`: 자동 재시도 반복을 막고 장소 카드와 네이버 지도 앱 열기를 제공한다.
- SDK 인증 오류: 운영 로그에는 Client ID 상태와 오류 코드만 기록하고 좌표·장소명은 기록하지 않는다.
- 플랫폼 패키지 장애: `MapPort` 구현을 자체 네이티브 플러그인으로 교체하고 일기·장소 데이터는 유지한다.

### 5.6 3차 검증 관문

Android API 24 실기기와 iOS 15 이상 iPhone에서 다음을 통과해야 출시한다.

- 지도 최초 열기, 반복 열기·닫기, 화면 회전, 백그라운드·포그라운드 복귀
- 현재 위치 권한 허용·거부·다시 묻지 않음과 수동 핀 지정
- 마커 100·500·1,000·5,000개에서 클러스터, 스크롤, 메모리와 프레임 측정
- Flutter 상태 갱신 시 지도 재생성 여부와 컨트롤러 해제 후 메모리 누수 측정
- 오프라인, 잘못된 인증, 이용 한도 초과와 네이버 지도 앱 미설치 대체 흐름
- 지도 위젯 생성·복귀·재생성 횟수와 콘솔 Usage 대조
- 장소 추가 전 백업, 2차 장소 백업과 3차 지도 도입 후 백업의 복원 호환성
- 공유 이미지·로그·크래시 보고서에 좌표와 GPS EXIF가 없는지 검사

## 6. 구현 순서

### 2차 장소 기록

1. `Place` 데이터베이스·백업 포맷 마이그레이션
2. 장소명 직접 입력 UI
3. 사진 GPS 후보 읽기와 현재 위치 1회 요청
4. 위치 카드, 수정·제거와 공유 선택 옵션
5. 좌표 기반 기상청 과거 날씨 제안
6. 암호화·권한 거부·백업 호환·개인정보 검증

### 3차 네이버 지도

1. 별도 기술 스파이크에서 양 플랫폼 최소 지도와 Usage 과금 단위 측정
2. `MapPort`와 네이버 지도 어댑터 구현
3. 장소 선택 지도와 상세 지연 로딩
4. 추억 지도, 마커 카드와 클러스터
5. 콘솔 한도·알림·인증 제한 설정
6. 실기기 성능·장애·비용·개인정보 검증
7. 3차 기능 플래그를 켜고 단계적 배포

## 7. 도입 시 다시 결정할 항목

- 2차에서 사진 GPS와 현재 위치를 모두 제공할지 여부
- 장소명이 없는 좌표를 허용할지 여부
- 추억 지도 마커가 많을 때 표시할 최대 기간과 최대 개수
- 지도 기본 카메라 범위와 마커 디자인
- 해외 사용자에게도 네이버 지도를 제공할지 여부
- 실제 Usage 기준 월간 활성 사용자당 평균 지도 호출 수와 운영 한도
- `flutter_naver_map` 유지 또는 자체 네이티브 플러그인 전환 여부
- 기상청 ASOS 라이브 30개 표본 결과와 과거 날씨 지원 기간
